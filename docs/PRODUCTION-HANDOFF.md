# Передача: что сделано в репозитории и что требует доступа к production

Дата: 28 октября 2026. Ветка: `claude/friendly-newton-h0a4fq` (основана на `prepare-contractor-landing`, PR № 3).

## Статус доступа к Beget

Из облачной среды production **недоступен**:

- `demchenkos.beget.tech` — DNS не резолвится (SSH невозможен);
- `zakondemchenko.ru:443` — egress-прокси отвечает 403 (политика сети среды).

Ограничения не обходились. Поэтому **не выполнены и не имитировались**: сравнение production с GitHub, поиск
генератора документов и платёжного шлюза, исследование MySQL и `workbench.zakondemchenko.ru`, резервная копия
и проверка восстановления, публикация. Публикация заблокирована до выполнения резервной копии (см. `PAID-CLIENTS-AUDIT.md`).

## ⚠️ Совместимость с production

`process_form.php` в репозитории может отличаться от рабочего (ветка `agent/b2b-legal-practice` ожидает от ответа поле
`telegramDeepLink`, которого в этом файле нет → на production, вероятно, другая версия). **Не копируйте `api/process_form.php`
на сервер.** После получения доступа нужно перенести в рабочий обработчик только три вещи: проверку `consent`, белый список
`source`/`service`, строку «Источник» в уведомлении. Фронтенд с `consent` нельзя выкладывать раньше, чем серверная часть
будет совместима (старый сервер просто проигнорирует поле — это безопасно; новый сервер со старым фронтендом отклонит заявки).
Порядок: сначала сервер, затем `script.js` и посадочная.

## Что нужно от владельца (одно действие)

Выберите один вариант:

1. **Рекомендуется:** запустить эту же задачу в Claude Code на вашем Mac (там работают ваши SSH-ключи и доступ к Beget):
   `cd` в клон репозитория → `claude` → «Продолжи по `docs/PRODUCTION-HANDOFF.md`».
2. Либо в настройках облачной среды (меню среды в заголовке сессии → Edit) разрешить сетевой доступ к
   `zakondemchenko.ru` и `demchenkos.beget.tech`. Учтите: среда ходит через HTTPS-прокси, прямой SSH (порт 22) может
   остаться недоступным — тогда нужен вариант 1 или доступ только к панели/FTP-over-HTTPS. Ключи и пароли в чат не присылайте —
   только в Network secrets/переменные окружения среды.

## План работ после получения доступа (по порядку)

1. Read-only инвентаризация `public_html` (и `workbench`): дерево, `.htaccess`, обработчики, генератор, платёжные файлы, cron.
2. Сравнение с `main` (`diff -rq`), список файлов, которых нет в Git; их **не удалять и не перезаписывать**.
3. Бэкап: `tar` файлов + `mysqldump --single-transaction` в каталог вне `public_html` (не в Git), `sha256sum`, тест восстановления
   в отдельной БД/каталоге, `docs`-план отката.
4. Сверка цен/оферты с production; снять `noindex` на посадочной только после подтверждения.
5. Перенос серверного патча `consent`/`source`, затем фронтенда; тестовая заявка с вымышленными данными: запись в БД,
   уведомление владельцу, автоответ.
6. Генератор и платёж — только тестовый режим шлюза; реальные платежи — отдельное согласование.
7. Аналитика: подключить `analytics.js` (счётчик подтвердить, согласие посетителя), цели `lead_saved` и подтверждённая серверная оплата.
8. Реклама — только после чек-листа готовности; запуск платных кампаний требует отдельного подтверждения (бюджет ≤ 15 000 ₽).
