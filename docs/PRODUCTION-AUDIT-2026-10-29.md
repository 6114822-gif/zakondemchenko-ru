# Проверка Beget и совместимый кандидат релиза

Проверено 29.10.2026 с Mac владельца. Это отчёт о проверках и подготовленных изменениях, не подтверждение публикации или готовности рекламы.

## Доступ и резервная копия

SSH работает через существующий alias `zakondemchenko-deploy`, без передачи ключей в чат. Рабочие корни: `/home/d/demchenkos/zakondemchenko.ru/public_html` и `/home/d/demchenkos/workbench.zakondemchenko.ru/public_html`.

Приватная копия находится на Mac вне репозитория и web root. Скопированы public_html обоих сайтов, private/private_store, payment_config.php; получены MySQL dump с single transaction/routines/triggers/events и отдельный согласованный SQLite online backup. SHA-256 зафиксированы в приватном BACKUP-MANIFEST.json. Распаковка и побайтовая проверка 241 публичного и 1437 приватных файлов успешны. Это файловый снимок во время работы сайта, не единая транзакция между всеми сервисами.

MySQL восстановлена в отдельной MariaDB на Mac, без TCP-порта. Импортированы пять таблиц, CHECK TABLE везде OK. SQLite integrity_check — ok. Для проверки установлена MariaDB через Homebrew; автозапуск не включался. Копия не покрывает внешний VPS, Robokassa, DNS и настройки панели Beget. Поэтому полной disaster-recovery копией всех внешних зависимостей её считать нельзя.

## Техническая карта

- Главная, `/uslugi/`, `/proverka/`, `/oplata/`, оферты, бизнес-страницы и статьи работают на основном домене. HTTPS GET проверены, это не доказательство оплаченного заказа.
- Web PHP по HTTP-заголовку: 8.5.12. Обычный SSH `php` — 5.6.40; отдельный `/usr/local/php/cgi/8.3/bin/php` — 8.3.33. Не запускать современные обработчики обычным `php` по SSH.
- `api/process_form.php` → MySQL `questions` + транзакционный `legal_crm_relay_outbox` → CRM. Ответ содержит `questionId`, `telegramDeepLink`, `autoReply`.
- Согласие уже проверяется сервером: допустимо только `consent=yes`. PR №4 с boolean true несовместим; рабочие API, functions.php и script.js нельзя заменять файлами main/PR.
- `api/queue.php` обслуживает внешний генератор: next/complete, защищён X-Worker-Token. Комментарий про локальный answer_worker.php устарел. В копии MySQL 12 вопросов, 2 без ответа, но ни одного неотвеченного за последние сутки; 5 outbox-записей отправлены. Факт получения адресатами не проверен. SSH к прежнему alias внешнего VPS завершился timeout; состояние его сервиса не установлено.
- `api/ai_chat.php` — отдельный чат через внешний AI relay; `api/widget_lead.php` — заявки виджета. Их не меняли.
- Robokassa: `api/legal_create_order.php`, `legal_payment_common.php`, `legal_payment_result.php`, `legal_order_status.php`; секреты в payment_config.php вне public_html. Реальные продажи включены, test mode выключен. Заказы — приватная SQLite. В снимке: один pending, один test_paid; реальных paid нет.
- Workbench — отдельное приложение с входом/подпиской, клиентскими досье, проверкой документов, проектами и DOCX. Private store вне web root. Health отвечает 200, ai=ok, 41 официальный акт, legalAccuracyVerified=false. В Chrome подтверждена активная сессия владельца. После отмеченного владельцем согласия выполнен синтетический тест без клиентских данных: проект получен, внутренний лист проверки показан отдельно. Чистовой экспорт ожидаемо заблокирован из-за полей в квадратных скобках. Штатной кнопкой скачан DOCX-черновик, ZIP/OOXML проверены, документ отрендерен bundled LibreOffice: одна страница без обрезки, поля выделены жёлтым. Внутренние замечания и названия клиентских досье в DOCX не попали. Проверен простой сценарий нового документа и draft export; проверка сложного договора, цветных правок, рецензирования и юридической корректности этим тестом не подтверждается.
- `crontab` в SSH-окружении недоступен; задачи панели Beget и внешнего VPS не подтверждены. Пустой сохранённый stdout не означает отсутствия cron.
- Сравнение main: 8 файлов совпадают, 19 различаются, 149 файлов есть только на production (включая старые резервные файлы). Секретные diff и клиентские данные не публикуются.

## Подготовленные изменения

1. Три файла посадочной из PR №3/4 с `consent=yes`, подтверждением `questionId`, безопасным Telegram deep link, опытом из задания владельца. `noindex` сохранён.
2. 7 900 ₽ за проверку договора и претензионные документы сверены с действующими страницами. 14 900 ₽ за арбитраж в актуальном прайсе не подтверждены: на новом кандидате указано согласование цены; действующие тарифы не изменены. 1 990 ₽ — отдельная письменная проверка в пределах оферты, не подготовка полного иска. Абонентская оферта: 39 000 ₽, до 12 часов/месяц и 5 активных досье, если отдельно не согласовано иное.
3. `assets/js/analytics.js` основан на рабочем файле: явный opt-in, отказ сохраняется, Webvisor выключен, query/hash удалены из передаваемого URL/referrer. Это ещё не проверка всех cookies и юридических документов сайта. Общая аналитика кликов может считать одно взаимодействие в нескольких разных целях; агрегировать их как заявки нельзя.
4. Отдельный patch рабочего process_form сохраняет source/service и доказательство согласия в JSON outbox в той же транзакции с вопросом. Не меняет схему questions и не трогает payment. Рядом SHA-256 исходника: применять только к совпадающей версии. Приём новых metadata центральной CRM пока не подтверждён. UTM кампаний и сквозное связывание с оплатами в этом релизе не реализованы.

- Node syntax, PHP lint и git diff --check прошли. PHP staging 8.5.11; Beget web 8.5.12.

## Публикация и откат

Production в этой сессии не изменён. PR №3/4 не сливались. Кандидат не содержит серверных конфигов, баз и секретов. main не является восстановленной полной версией production.

Перед выкладкой: согласовать новый публичный текст; проверить персональные данные/оферты; завершить sandbox провайдера (простой авторизованный тест генератора и DOCX-черновика уже пройден); подтвердить получение контрольного обращения и работу внешнего worker. Не называть текущий релиз проверенной платёжной системой.

Минимальный manifest: landing-podryad.html, assets/css/landing-podryad.css, assets/js/landing-podryad.js, assets/js/analytics.js; API — только отдельный patch поверх совпадающего baseline. Перед каждым изменением повторно сравнить server hash, сохранить текущий файл приватно, загрузить новый вне public_html, проверить синтаксис/хеш и атомарно переименовать. analytics.js влияет на другие страницы: проверять и их.

Откат: вернуть сохранённые версии изменённых файлов, убрать только новые пути. Не восстанавливать старые базы поверх новых заявок/платежей. Рекламу не запускать до функциональной приёмки; бюджет и конкретные кампании требуют отдельного решения владельца.
